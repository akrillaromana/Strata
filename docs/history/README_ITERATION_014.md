# Итерация 014 — Q6_K native down/MMVQ и строгая принадлежность Q8_0 PLE модели

**Основа:** полный исходный ZIP итерации 013; последний подтверждённый GitHub-коммит `f6d07a8` (012+013). Итерация 014 ещё не опубликована.

## Что реализовано

1. `src/kernels/cuda/iq_kernels.cu`: Q6_K (GGML type 14) теперь появляется **во всех трёх** opt-in CUDA списках форматов: gate/up, down и MMVQ. До этого `d_qk(14)` возвращал 0, `native_expert_supported(14,14,...)` отказывал в down, а `iq_row_bytes(14,n)` возвращал ноль. Добавлено 210 байт на блок 256 значений, `static_assert(sizeof(block_q6_K)==210)`. Компиляционный флаг `STRATA_Q6K_EXPERTS` по умолчанию **OFF** и по-прежнему требует `STRATA_MMQ_KQUANTS`.
2. `src/kernels/native_grouped_parity.cpp`: Q6_K down включён в GPU parity matrix при компиляции с тем же opt-in флагом. Ранее тесты перебирали Q6_K только для gate/up.
3. `src/program/generate.cpp` + `include/strata/artifact/native_ple_source.hpp`: при `--ple-require-type Q8_0` движок открывает `GgufModel` для полного комплекта `--native`-шардов, требует единственную модельную таблицу и отказывает стороннему Q8_0 sidecar, даже если её тип и размеры совпадают. Проверяется тождественность файла исходному шарду (с поддержкой эквивалентного написания пути), диапазон тензора; авто-выбор сохраняется. Путь Q4/IQ3 не меняется.
4. Дополнительные тесты: C++ `native_ple_source_test.cpp`, 9 статических контрактов Q6_K, новый тест строгой принадлежности Q8_0. Профили Q4/Huihui/IQ3_S/Q8 и личные пути E:/R: **не изменялись**.
