# Итерация 013 — собственная Q8_0 PLE / n-gram таблица

Главная задача: убрать чужую IQ4_NL PLE из личного профиля Unsloth Q8_0, использовать исходный Q8_0 тензор `per_layer_token_embd.weight` из модельных GGUF-шардов и не допускать незаметного fallback.

Изменения: `src/program/generate.cpp` (новая проверка `--ple-require-type Q8_0`, ранняя проверка GGUF и повторная после открытия читателя); `tools/q8_ple_preflight.py` (оффлайн-инспекция заголовков); Q8 JSON в двух зеркальных папках; проверки `tools/test_q8_ple_preflight.py` и `test_personal_profiles.py`; защита арифметики `src/ngram/ple_reader.cpp`; сняты ошибочные дополнительные переводы строк из PS1 (причина `git diff --check` ошибки на предыдущей итерации).

`--native` автоматически обнаруживает PLE-шард модели. `--ple-gguf` с внешним IQ4_NL больше нет. Требуется GGUF, содержащий **настоящий Q8_0** PLE тензор `[160, 320001536]`, 170 байт на строку. Без такого тензора программа выдаёт ошибку; преобразование чужого IQ4_NL в Q8_0 не производится.

**Ограничение:** реальный GGUF/веса пользователь не предоставлял, исполняемый файл пользователя не обновлялся; проверены исходники и синтетические заголовки, не полноценный прогон модели. Пользовательская E:-установка не затронута.
