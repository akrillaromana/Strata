# Аудит совместимости моделей — итерация 006

## Как проводилось сравнение

Источник 1 — наш форк v0.1.39, полный снимок после итерации 005. Источник 2 — предоставленный `Strata-main(1).zip`: новая версия исходников с `docs/MODELS.md` и `docs/UNSLOTH_Q6.md`. Рассматривались конкретные пути чтения, квантования, экспертных CUDA-ядер и подготовки пакетов, а не только заявления документации. Новые части донора не копировались поверх старой архитектуры без выборочной интеграции. Не все функции новой основной ветки можно безопасно перенести за одну итерацию.

**Важно.** Документация донора о Q6_K содержит несовместимые утверждения о статусе 0.1.40/Q8 PLE, поэтому её нельзя считать доказательством готовности. Контрольные проверки настоящих данных остаются обязательными. Формулировка «поддерживается тип Q8_0» не равнозначна «любой Q8_0 GGUF загрузится».

## Наши пользовательские решения

Все частные конфигурации из `tools/windows/q4-local-profiles/` (IQ3_S, оригинальная UD-Q4_K_XL, Huihui UD-Q4_K_XL) сохранены. Параметры `spec=4`, `spec-min-p=0.5`, `suffix-draft=0`, контекст 262144, `kv=int8`, `kv-resident=32768`, бюджет резидентности 80 ГиБ, `pcie-frac=0`, отключённая адаптация, локальный пакет и профиль экспертов не переписывались. Их конкретные абсолютные пути E:/R: продолжают быть привязанными к первоначальному компьютеру. Серверные host `0.0.0.0` и порт 8080 для этих профилей не менялись. Новые примеры Q6/Huihui Q8 — на `127.0.0.1:8081` для **изолированного теста**, без воздействия на рабочую установку.

## Что брать из донора в следующих итерациях

1. Тесты паритета PLE для реального GGUF (Mmap/Direct): проверить отдельные файлы и их совместимость с текущей веткой, не обещать уже присутствующие в архиве файлы, которых нет.
2. Недостающие виды нативных экспертов и комбинации gate/up/down (например, в некоторых Q4_0 и Q6_K вариантах) — по инвентаризации форматов, CUDA-хосту и тестам.
3. Дополнения к `tools/iq_pack.py` для разбиений с большим числом шардов и Q8_0, не изменяя формат уже существующих Q4-пакетов.
4. Привязка к UI «семейств моделей»: обнаружение реального GGUF, подготовка индивидуального пакета, предупреждения о размерах, проверка соответствия памяти.
5. Реальные GPU тесты каждого квантования: `native_expert_parity`, `native_grouped_parity`, предзаполнение, самопроверка n-gram, старт/ответ/качество.

## Почему не обещаем полную поддержку

- Нет CUDA-компилятора и RTX 3060 в среде сборки архива: новые CUDA-ветви Q6_K не удалось скомпилировать на GPU.
- Пользователь не приложил GGUF Q6_K или Huihui Q8_0; ни загрузка, ни выдача верного ответа ими не проверены.
- Нативность относится к экспертам и PLE, не к некоторым малым плотным тензорам, преобразуемым pack через `--compat-bf16`.
- Полный перенос остальных возможностей новой версии требует отдельного анализа архитектуры и тестов, а не копирования обновлённых компонентов целиком.
