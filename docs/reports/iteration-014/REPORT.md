# Итерация 014 — анализ и кодовые изменения

Базовая опубликованная версия: `f6d07a8` (012+013) на `strata-v0.1.39-custom`.

## Фактический дефект Q6_K

В итерациях 006–013 существовали `Fmt<14>` (Q6_K CUDA dot) и gate/up type14, но:
- `STRATA_D_FMTS` **не содержал Q6_K**, потому `d_qk(14)==0`;
- `STRATA_MMVQ_FMTS` **не содержал Q6_K**, поэтому `iq_mmvq(14)` завершался `unsupported`;
- `iq_row_bytes` **не имел case 14**, возвращал 0 для 210 B/native GGML Q6_K block.

Все три ветви теперь opt-in поддерживают Q6_K. Размер блока проверяется на этапе компиляции. Это закрывает конкретный gap в GPU кодовой маршрутизации, но не подтверждает CUDA точность/производительность до полной сборки и отдельной фазы испытаний.

## Фактический дефект Q8_0 source

`--ple-require-type Q8_0` в 013 проверял тип и геометрию у **любого** выбранного `--ple-gguf`, включая внешнюю стороннюю таблицу другого происхождения. 014 заставляет выбирать только уникальный тензор оригинальной GGUF-модели, сравнивает идентичность файла и границы модели. Это гарантирует отказ от стороннего Q8_0 sidecar по ошибке/подмене. Дополнительная проверка после открытого PleReader из 013 оставлена без изменений.

## Отдельные входы для полной проверки позднее

Q6_K полный GPU — opt-in `STRATA_Q6K_EXPERTS=ON`, `STRATA_MMQ_KQUANTS=ON`; полную CUDA сборку и реальную модель запрещено требовать у пользователя сейчас. Huihui Q8_0 отдельной матрицы различий ещё требует. Взвешенные таблицы PLE и Q6_K GGUF не включать в ZIP/GitHub.
