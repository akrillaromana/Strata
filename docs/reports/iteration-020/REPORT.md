# Отчёт Strata 020: консервативный дополнительный shared-MTP GGUF

**Исходная база:** полный архив `Strata-custom-v0.1.39-iteration019-FULL.zip`, опубликован на GitHub SHA `7ac3301` (подтверждён по пользовательскому журналу).

## Изменённая кодовая функциональность

1. Новый `tools/mtp_shared_source.py` соединяет два независимых GGUFReader только при явно заданном companion. Отдельный файл может внести отсутствующие shared gate/up/down-проекции и, если присутствует, BF16 scalar gate. Для BF16 и Q8_0 проверяются type ID, физическая форма, отсутствие дублированных имён и строго разрешённые имена тензоров. Маршрут не способен брать routed experts, attention или FC из companion.
2. Дубли shared-тензоров разрешены исключительно при полном совпадении типа, формы, dtype и физических байтов. В отличие от float compare, сравнение не переинтерпретирует BF16 и не меняет Q8_0 scale или codes.
3. `tools/mtp_original_rt.py` получил `--shared-gguf`: проверка двух исходников и объединённой схемы **до создания выходного каталога**. Обе mmap-ссылки остаются живыми, преобразование выполняется существующим проверенным `--experts native` или явно разрешённым Q2_0 путём. Результат маркируется в `source_policy.json` (`origin_verified: false`, видимые имена файлов и добавленные тензоры). Проверка `mtp_rt_validator.py` остаётся обязательной до атомарного rename.
4. `data/personal_models.json` дополнен двумя кандидатными парами `BF16 ↔ shared-BF16`, `Q8_0 ↔ shared-Q8_0`, с явной пометкой «кандидат, не подтвержден». Восемь записей о моделях и абсолютные пути к ним не изменены.
5. `tools/test_mtp_shared_source.py`: 20 самостоятельных отрицательных и интеграционных проверок, в том числе отсутствие routed experts, конфликт payload, неверный тип scalar gate, геометрия Q8_0, bad names, добавление optional gate и построение runtime на малых тензорах.

## Чего этот код НЕ гарантирует

- **Нет исходных GGUF весов или полных метаданных:** имена `shared-BF16`/`shared-Q8_0` не доказывают, что эти GGUF содержат требуемые тензоры. Код отклонит неподходящую структуру; для другой схемы понадобится корректная адаптация по фактическим данным. Совпадение геометрии не является криптографическим доказательством происхождения из одного checkpoint.
- Отсутствует автоматический merge несовместимых исходных тензоров. Нет silently swapped weights или fallback на Q2_0.
- Это **не CUDA сборка** и не выполнение модели, и не завершение полной поддержки Vision, Huihui Q8_0, Unsloth Q6_K либо JSON Schema constrained decoding.
- Пользователь на текущем этапе требует только разработку кода, без локальных установок/запуска CUDA на его машине.
