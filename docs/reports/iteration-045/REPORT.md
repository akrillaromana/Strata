# Strata Fork — итерация 045: зависимость gguf-py при сборке Q8_0

Дата: 12 октября 2026 года. Основа: полный архив `Strata-Fork-IQ3S-iteration-044.zip`.

## Подтверждённая ошибка Windows

Пользователь выполнил `START-Q8-RAM.ps1 -PreparePack -AllowBf16Conversion`. Проверка трёх запускателей прошла; исходные шесть GGUF распознаны. Проверка заголовков показала настоящую таблицу PLE `Q8_0` во втором шарде (около 50,66 ГиБ). Сборщик `tools/iq_pack.py` сообщил:

```
llama.cpp's gguf-py was not found: run setup.py (it clones llama.cpp into third_party/), or set STRATA_GGUF_PY
```

Это ошибка обнаружения вспомогательного пакета Python, **не ошибка загрузки CUDA и не ошибка данных модели**. Используемый CMake `FetchContent` уже извлекает ту же закреплённую ревизию llama.cpp в `build-iq3s-ninja-release/_deps/strata_llamacpp-src`. Однако `tools/_paths.py` ранее не искал там `gguf-py`.

## Внесённые исправления

1. `tools/_paths.py`: добавлены каталоги исходников llama.cpp, скачанных CMake, и дополнительные сборочные каталоги `build*`. Приоритет отдан явно заданному `STRATA_GGUF_PY` и локальной установленной библиотеке; неполные каталоги без `gguf/__init__.py` отвергаются.
2. `tools/ensure_gguf_py.py`: новая проверка фактического импорта `GGMLQuantizationType`, `quants`, `Q8_0` и `BF16`. Если существующие каталоги непригодны, только при параметре `--install-if-missing` загружается архив закреплённой ревизии `3cf03257f219afbe7334045ff7c6a06ac68c627d` по HTTPS. Извлекается **только** `gguf-py`, со строгой проверкой пути, ограничения размера и отказом от символьных ссылок; сохраняется лицензия upstream. Не устанавливаются пакеты в системный Python, не перезаписывается существующий каталог.
3. В обоих внутренних `START-Q8-RAM.ps1` проверка gguf-py вызывается до записи данных Q8-пакета и до обращения к RAM-диску. Если она не прошла — выводится явная причина и исполнение прекращается.
4. Недописанный `unsloth-q8_0.building` от прошлой попытки сохраняется. Новая попытка использует уникальный временный каталог `unsloth-q8_0.building-045-<идентификатор>`; прежний каталог не удаляется, чужие пакеты не изменяются.
5. `START-Q8-RAM.ps1` и `tools/TEST-MODEL-LAUNCHERS.ps1`: версия обновлена до 045, добавлены проверки наличия нового компонента.
6. `tools/test_gguf_dependency.py`: тесты приоритетов поиска, CMake, неполных каталогов, безопасного распаковывания, лицензии и запрета загрузки без явного параметра.

## Проверки, выполненные здесь

- Модули Python проверены `py_compile`.
- Проверки `tools/test_gguf_dependency.py`, `tools/test_native_ple_key_policy.py`, `tools/test_gguf_header_hardening.py` — 21/21 успешно.
- Оба внутренних Q8-запускателя сверены побайтово после правки.
- Повторная сборка движка **не нужна**: C++/CUDA не изменены.

## Границы подтверждения

Здесь отсутствуют Windows 10, PowerShell 7.6.6, CUDA, AIM RAM-диск, шесть настоящих GGUF Q8_0. Поэтому полностью подготовленный пакет, его загрузка и генерация Q8 **не подтверждены**. Если Python-библиотека находится по CMake-пути, скачивания не будет; альтернативная загрузка требует доступного GitHub и не проверена на Windows. Округление отдельных проекций BF16 разрешается только через явный `-AllowBf16Conversion` и может менять значения весов; оригинальные эксперты и таблица PLE остаются исходными.
