# Итерация 016 — MTP runtime: валидация индекса и источника

Основа: полный архив 015, последнее **подтверждённое** пользователем состояние GitHub:
`baae31c`, ветка `strata-v0.1.39-custom`. 016 пока не опубликована.

## Подтверждённые кодовые изменения

1. `include/strata/core/mtp_manifest.hpp` — CPU-only контракт для `dense.txt`:
   `q8_0` в блоках 32→34 байта, `bf16` 2 байта/элемент,
   `f32` 4 байта/элемент; проверяются unsigned размеры, умножения без overflow,
   реальные диапазоны `dense.bin`, выравнивание 256, перекрытия,
   повторы имён, отсутствующие девять обязательных Q8_0-проекций,
   посторонние колонки, пустые и слишком длинные записи.
2. `src/core/mtp.cpp` — этот контракт вызывается **до** выделения GPU-памяти.
   Проверяется точная длина `experts.bin` для количества экспертов и
   жёстко обрабатываются ошибки CUDA-копирования. Вместо невалидной
   интерпретации исходного GGUF по пути `--mtp` возвращается сообщение
   о требуемом формате runtime.
3. `tools/mtp_runtime_contract.py` + `tools/mtp_rt.py` — до создания или
   перезаписи выходных файлов проверяются обязательные поля исходного
   packed MTP GGUF: Q2_0-эксперты (ggml type 42) с физическими формами
   `(512,1280,720)` и `(512,2560,180)`, BF16 dense/F32 norms, имена,
   полнота. **Исходный BF16/Q8_0 MTP GGUF из пользовательского каталога не
   маскируется под Q2_0 runtime** и не перезаписывает выходное хранилище.
4. Добавлены `tests/cpu/mtp_manifest_test.cpp` и
   `tools/test_mtp_runtime_contract.py` (15 C++ негативных/позитивных
   сценариев, 10 Python проверок); 107/107 широких Python и 55/55 JS.
5. Личные профили, пути `E:\ai\`/`R:\`, модельный реестр восьми
   вариантов, native Q8_0 n-gram, существующие Q6_K/IQ3_S/Q4_K_XL
   решения **не изменялись**. Нет сборки CUDA, реальных GGUF/Windows/GPU
   и доступа к рабочей установке владельца.

## Ограничения

- Новые защиты MTP не являются полноценным конвертером всех четырёх
  Unsloth BF16/Q8_0/shared GGUF в `--mtp` runtime и не включают их
  вычислительную обработку. Это **открытая задача**.
- Не заявлять полной совместимости Q6_K, Huihui Q8_0, MTP, vision;
  нет весов и GPU испытаний. Кодовая часть этих функций остаётся открытой.
