# Strata Fork — отчёт итерации 041

Дата: 12 октября 2026 года. Базовый архив: `Strata-Fork-IQ3S-iteration-040.zip`. Статус: **промежуточный; исходный код исправлен, калибровка на пользовательском PowerShell пока не подтверждена**.

## Полученный результат и доказанная причина

На Windows 10, PowerShell 7.6.6, пользователь запустил `TUNE-MODEL.ps1 -Apply`, выбрал пункт № 1 (`qwen3.8-flash-next-iq3_s`, `strata-iq3_s-RAM.json`). Состоялся первый замер: `warmup | PCIe=0,26 | MTP=0,75 | 30,1 ток/с`. Далее PowerShell сообщил: «Не удается найти позиционный параметр, принимающий аргумент `0,75`».

В скрипте 040 объявлена функция `Compare`, но `Compare` — встроенный псевдоним `Compare-Object` в PowerShell. При вызове `Compare $PcieValues 'pcie' $BaselineSpec` выполнялась встроенная команда, а не написанная функция сравнения. Параметр `0,75` был передан `Compare-Object` как лишний позиционный аргумент. Поэтому причина **не** в культуре десятичного разделителя, сервере, CUDA или модели: это конфликт имён в PowerShell.

Ранее при сканировании корня выводилось «Пропущен повреждённый профиль ...shared-settings.json: Не удалось найти свойство `model_name`». Файл общих настроек **не является повреждённым профилем**; он не должен считаться конфигурацией модели при включённом StrictMode. Третья проблема — одинаковые шаблоны в корне и двух каталогах копий повторялись в меню до трёх раз.

## Изменения

1. `TUNE-MODEL.ps1`:
   - Внутренние функции переименованы: `Compare` → `Measure-TuningCandidates`, `Sample` → `Invoke-TuningSample`, `Median` → `Get-TuningMedian`, `Score` → `Get-TuningScore`. Все их вызовы обновлены вручную. Это устраняет установленный конфликт псевдонима и уменьшает риск новых конфликтов.
   - `Get-Profile` **до чтения** полей проверяет, что `model_name`, `exe`, `args` действительно присутствуют. Служебные JSON без этих полей пропускаются без ложной диагностики «повреждённого профиля».
   - Файлы `*.shared-settings.json` и `*.autotune.json` явно исключены из обнаружения профилей. Остаётся поддержка произвольных имён JSON-файлов, а не только имени, начинающегося с `strata-`.
   - Повторяющиеся имена конфигураций из трёх каталогов показываются один раз. Приоритет у рабочей версии в корне проекта, затем у пользовательской копии, затем у шаблона из `tools/windows/q4-local-profiles`. Если одноимённые профили намеренно отличаются, конкретный вариант всегда доступен через `-ConfigPath`.
   - При относительном пути к `exe` и отсутствии `cwd` используется каталог выбранного профиля; ошибки отсутствующих свойств не допускаются.
2. `tools/TEST-TUNE-MODEL.ps1`: добавлена неразрушающая проверка синтаксиса через штатный разборщик PowerShell и пересечений названий функций со встроенными псевдонимами. Запуск сервера или доступ к GGUF не требуется. Наличие этого теста не заменяет его фактическое выполнение на Windows.
3. `docs/reports/iteration-041/`: данный отчёт, оставшиеся задачи, точные команды для пользовательского PowerShell.
4. `CONTINUE_PROMPT.md`: добавлена сводка текущей итерации с полным сохранением предыдущего контекста.

## Не изменено

Ни `serve/server.py`, ни `src/`, ни `include/`, ни сборка CUDA, ни профили RAM/PLE/MTP, ни ключи API, ни веб-интерфейс. Никаких GGUF в возвращаемом архиве нет и внешние пользовательские модели не затронуты. Движок `strata.exe` **не требуется пересобирать**: ошибка находилась исключительно в PowerShell-калибровщике.

## Возврат и дальнейшие действия

После самостоятельной распаковки пользователем архива в `E:\ai\Strata-Q4-Fork`, при уже запущенном сервере выбранной модели — **в отдельном окне PowerShell**:

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force
Set-Location 'E:\ai\Strata-Q4-Fork'
& '.\tools\TEST-TUNE-MODEL.ps1'
& '.\TUNE-MODEL.ps1' -Apply
```

Калибровщик опять спросит номер модели (для той же IQ3_S — выбрать её рабочий `strata-iq3_s-RAM.json`). Он не меняет настройки без подтверждённого ускорения >=3% и явного `-Apply`; результаты будет применять только следующий запуск соответствующей модели. При сбое передать текст ошибки и частичный вывод. Если пройдёт полностью — передать итоговую скорость и `logs/autotune/<ключ>-LAST.json`.
