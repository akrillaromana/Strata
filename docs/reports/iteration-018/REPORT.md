# Strata Custom — итерация 018: нативные MTP BF16/Q8_0 routed experts

**Исходная база:** 017, последний подтверждённый опубликованный GitHub коммит `2946947`.
**Работа ограничена исходниками.** Нет CUDA-сборки, запуска GGUF или изменения машин владельца.

## Реализовано

1. `tools/mtp_original_rt.py`: добавлен **`--experts native`** наряду с прежним строго opt-in lossy `--experts q2_0 --allow-lossy-expert-conversion`. Новый маршрут сохраняет оригинальные физические BF16/Q8_0 байты routed gate/up/down для каждого эксперта, без преобразования к Q2_0; отличающийся тип down допускается. Плотные матрицы пока обрабатываются прежним кодом, т.е. BF16 dense→Q8_0 может квантизоваться, если dense требует Q8_0.
2. `tools/mtp_native_layout.py` и `include/strata/core/mtp_native_layout.hpp`: единый строгий протокол `experts.txt` с типами `bf16|q8_0`, числом экспертов и геометрией, вычислением байтов и запретом переполнений, несоответствия длины `experts.bin` и неизвестных вариантов.
3. `src/core/mtp.cpp`, `include/strata/core/mtp.hpp`: выбирают новый путь **по наличию** `experts.txt`; повреждённый файл / dangling symlink / неверная геометрия не должны молча переключаться на Q2_0. Загрузка MTP всё ещё проверяет `dense.txt` через 016. VRAM рассчитывается по фактическому размеру нативных экспертов. Дополнительный persistent scratch выделяется до графового захвата.
4. `src/kernels/cuda/mtp_native_experts.cu` и заголовок: CUDA GEMV gate/up для BF16 или Q8_0, SwiGLU, down GEMV в float32, токен и эксперт выбираются по GPU ids `[T*K]`. Оба типа независимо; результат `[T*K,H]` сохраняет интерфейс `moe_combine`, используется в prompt prefill и draft через общий `record_forward`. Нет превращения экспертов в Q2_0 и GPU аллокаций внутри графового захвата.
5. CMake включает новое CUDA-ядро в `strata_kernels` и CPU-only unit `mtp_native_layout_test`. Старый Q2_0-код сохранён, личные BAT/PS1/JSON и пути E:/R: не тронуты.
6. Python валидатор runtime обрабатывает оба формата; единые проверки размеров, локальные mini BF16/Q8 GGUF round-trip, mixed gate/down, отказ при повреждённом манифесте, non-finite Q8_0 scale, числовой CPU oracle для пары GEMV/SwiGLU.

## Геометрия и стоимость памяти

- Реальная исходная геометрия MTP: `N=2560`, `FF=640`, `NE=512`.
- Q8_0/Q8_0: `5,222,400` байт/эксперт = `2,673,868,800` байт всех routed experts (~2.49 GiB).
- BF16/BF16: `9,830,400` байт/эксперт = `5,033,164,800` байт (~4.69 GiB).
- Смешанные исходные типы вычисляются независимо. Это существенно больше прежних ~0.7 GiB Q2_0; если GPU недостаточно, загрузчик возвращает ошибку выделения памяти, **никакого неявного lossily converted fallback**.
- Dense BF16 projections, требующие Q8_0 ядро, и дальше могут быть приведены к Q8_0; заявленная «lossless» относится только к *routed expert weights*.

## Проверки

- CPU-only C++ `mtp_native_layout_test.cpp`: 13 проверок корректных/неверных форматов (compiled `g++ -std=c++17 -Wall -Wextra -Werror` и запущено).
- Python: **129/129** выбранных профильных и серверных тестов (в т.ч. 9 новых native runtime checks + прежние MTP source/regression).
- Node.js: **55/55**.
- Python числовой CPU oracle: BF16/Q8_0 packed source → native experts.bin → gate/up/SwiGLU/down, без повторного квантования экспертов.
- Проверить после упаковки 017→018 ZIP, Git staged diff и SHA256. **CUDA-код не компилировался и не исполнялся**; заявлять полную GPU корректность/ускорение нельзя.

## Что остаётся

- Фактическая CUDA-компиляция и GPU parity этого пути не входят в текущий этап; в исходниках ещё требуется оптимизированный Q8/BF16 grouped compute, если низкая производительность окажется проблемой. Реальные веса не предоставлены.
- `shared-*` MTP GGUF: действующий source contract требует routed `gate_up_proj` и `down_proj`. Shared-only варианты не могут запускаться без знания фактической схемы файла; не объединять неизвестные модели.
- Нативная end-to-end поддержка Q6_K, Huihui Q8_0 с собственной PLE, остальные MTP/full vision, токенное JSON Schema constrained decoding и интеграции донора 0.1.41 по-прежнему в P0/P1. Общая готовность кода не 100%.
