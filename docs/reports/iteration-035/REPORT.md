# Отчёт об итерации 035 — загрузчик DLL Windows для IQ3_S

Дата: 11 октября 2026 года. Основа: полный архив `Strata-Fork-IQ3S-iteration-034.zip`.

## Полученная диагностика

Пользователь успешно подготовил R:, обе части GSQ-RCO IQ3_S обнаружены. Движок `engine\strata.exe` завершается до собственной записи в журнал с кодом `3221225781 (0xC0000135)`. Это код загрузчика Windows `STATUS_DLL_NOT_FOUND`: какая-то обязательная DLL не разрешилась. Он **не доказывает**, что отсутствует именно CUDA, Visual C++ или ggml. Разделить эти случаи возможно только дополнительной проверкой зависимостей. Обычный журнал stderr пуст, поскольку исполняемый файл мог завершиться ещё до вызова `main()`.

## Исправления

1. Добавлен корневой `STRATA-WINDOWS-RUNTIME.ps1`, написанный вручную для PowerShell 7. Он определяет каталоги DLL из исходного каталога `engine`, локальной сборки Ninja, точного CUDA Toolkit из `CMakeCache.txt` (с резервными вариантами из `CUDA_PATH` и `nvcc.exe`) и подходящего каталога Microsoft.VC143.CRT в Visual Studio Build Tools 2022. Не копирует системные DLL, не устанавливает программы, не меняет системный PATH.
2. Процессный PATH дополняется обнаруженными каталогами перед созданием дочернего Python-сервера. `serve/server.py` и далее `strata.exe` наследуют это окружение. Сгенерированное поле конфигурации `lib_dirs` дополнительно содержит эти же пути для прямого запуска сервера через Python.
3. Перед использованием GGUF, очисткой временного каталога и обращением к RAM-диску выполняется быстрый тест `strata.exe --help`: успех означает успешную загрузку статически импортированных DLL без выделения памяти под модель. Ожидание ограничено 15 секундами, в частности на случай модального диалога Windows.
4. При неудаче через установленный Visual Studio `dumpbin.exe /dependents` создаётся `logs\iq3s\DLL_DIAGNOSTICS_LAST.txt`: проверка непосредственных и доступных транзитивных импортов, отсутствие каждого обнаруженного DLL; число проверяемых PE-файлов ограничено 80. Отчёт не претендует на обнаружение библиотек, которые программа подгружает динамически в произвольной точке исполнения.
5. Обновлены **все три одинаковые копии** `START-IQ3S-RAM.ps1` (корень, `PERSONAL_START_E_ai_Strata-Q4-Fork`, `tools/windows/q4-local-profiles`). Проверена их идентичность.
6. `BUILD_AND_START_IQ3S.ps1` после успешной сборки и размещения движка выполняет тот же тест загрузчика.
7. `GET-IQ3S-DIAGNOSTICS.ps1` выполняет безопасную проверку `--help`, выводит актуальную диагностику зависимостей и различает отчёт об ошибке от уже устаревшего отчёта после успешного запуска.
8. Обновлён `CONTINUE_PROMPT.md` и очередь оставшихся задач; имя установки остаётся строго `E:\ai\Strata-Q4-Fork`. Процесс распаковки пользователь выполняет самостоятельно.

## Ограничения проверки

- Изучен исходный код CMake, сервера Python, запускающего PowerShell и программы C++: `src/program/generate.cpp` действительно завершает `--help` с кодом 0 без загрузки модели, если динамический загрузчик успешно создал процесс.
- Совместимость PowerShell на Windows, точный состав доступных CUDA DLL и запуск собранного `strata.exe` проверить в текущей Linux-среде нельзя. **Нельзя считать, что ошибка 0xC0000135 уже гарантированно устранена.** Необходимо получить пользовательский результат.
- C++/CUDA файлы в этой итерации не менялись, повторная сборка бинарного файла не требуется.
- Исправления не трогают исходные GGUF, папки данных модели и содержимое второго сегмента на R: при отказе проверки DLL.

## Выполнение пользователем после самостоятельной распаковки

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force
Set-Location 'E:\ai\Strata-Q4-Fork'
try { & '.\START-IQ3S-RAM.ps1' } catch { Write-Host "Ошибка запуска: $($_.Exception.Message)" }
& '.\GET-IQ3S-DIAGNOSTICS.ps1'
```

При неудаче сохранить `E:\ai\Strata-Q4-Fork\logs\iq3s\DIAGNOSTICS_LAST.txt` и `DLL_DIAGNOSTICS_LAST.txt` (если создан). При успехе проверить `http://127.0.0.1:8080/v1/models`, а затем действительную генерацию.

## Следующая итерация

Если отчёт DLL назовёт отсутствующую библиотеку, исправить конкретный путь или установку соответствующего проверенного компонента. Если `--help` работает, но загрузка модели завершится иначе, анализировать **новый** код и журналы загрузки весов, не возвращаться к не подтверждённым гипотезам. После готовности API выполнить `/v1/models`, `/v1/chat/completions`, повторный запуск IQ3_S и контроль качества.
