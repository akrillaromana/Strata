# Итерация 019 — нативные BF16 dense для MTP

**Исходная база:** полный код итерации 018, опубликованный коммит `8f522b1` ветки `strata-v0.1.39-custom`.
**Сфера:** только разработка исходников форка. Модельные веса, `E:\ai\Strata-Q4-Fork`, RAM-диск `R:` и рабочие личные конфиги не менялись.

## Реализовано

1. `tools/mtp_original_rt.py`: `--experts native` сохраняет исходные **BF16 или Q8_0 dense-проекции побайтово** наряду с уже существующим lossless BF16/Q8_0 routed experts. Исходные BF16-проекции не превращаются в Q8_0, некорректные BF16/NaN отклоняются. `--experts q2_0 --allow-lossy-expert-conversion` оставлен в прежнем формате Q8 dense для обратной совместимости.
2. `include/strata/core/mtp_manifest.hpp` и `tools/mtp_rt_validator.py`: требуемые девять dense-проекций теперь допускают BF16 и Q8_0 (длина и физическая раскладка проверяются). Добавлена проверка **точной геометрии** матриц на основании параметров модели до GPU-загрузки, исключающая работу по чужим/обрезанным весам.
3. `src/core/mtp.cpp`: каждому из шести fc/attention dense GEMV выбирает тип-специфичный вызов — BF16 F32-activation CUDA GEMV без перепаковки либо существующий Q8_1 MMVQ. Три shared expert projection передают нативный BF16 type ID в shared-ядро. Внешний layout экспертов Q2_0 и native BF16/Q8_0 не менялся.
4. `src/kernels/cuda/shared_expert.cu`: single и multi токен shared expert поддерживают BF16 gate/up/down. Для BF16 down SwiGLU вычисляется в FP32 и **не** переквантовывается в Q8_1 перед BF16 matmul. Для Q8_0 прежние оптимизации остались. Shared scalar BF16 gate не затронут.
5. `src/prefill/prefill.cpp`: для больших батчей скоростной путь остаётся Q8_0-only, BF16 dense явно направляется на существующий `MtpDrafter::prefill`, который теперь использует BF16 GEMV; исходные BF16 байты не интерпретируются как блоки Q8_0.
6. Регрессии: новый `tools/test_mtp_dense_bf16.py` проверяет побайтовую точность dense BF16/Q8_0, смешанные варианты, отклонение некорректных тензоров и совместимость старого Q2_0. `tests/cpu/mtp_dense_bf16_test.cpp` проверяет матричную геометрию и обе комбинации типов. Тест подключён в `CMakeLists.txt`.

## Статус и ограничения

Вычислительный CUDA-путь написан, но **не собран и не запускался** в пользовательском GPU окружении, поэтому работоспособность на реальных весах не подтверждена. Проверки CPU и Python не являются подтверждением качества/скорости CUDA. Все четыре исходных Unsloth MTP GGUF, особенно shared-only, не исследовались по реальным метаданным: **shared-only нельзя подменять чужими routed experts**. Для полноценной кодовой готовности ещё нужны этот протокол, Huihui Q8_0, Unsloth Q6_K, vision/mmproj, token-level schema и другие открытые задачи. Реальная CUDA сборка и испытания отложены самим владельцем и не используются как метрика готовности кода.
