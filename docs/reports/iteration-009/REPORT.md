# Strata Custom 0.1.39 — итерация 009

## Основа и статус Git

Исходник: полный архив итерации 008 (не ветка донора). По представленному пользователем результату `git push` **008 уже опубликована**: `7d64b23` в `strata-v0.1.39-custom`, `https://github.com/akrillaromana/Strata`. Итерация 009 существует пока только в этом полном архиве; GitHub ещё НЕ обновлён.

## Реальные изменения кода

1. `tools/iq_pack.py`: PLE-ключи `IQ3_XXS` и `IQ4_XS` остаются в нативном GGUF/NativeDense, как уже было реализовано в C++ `src/core/native_dense.cpp` и `src/kernels/cuda/native_mmvq.cu`. Ранее упаковщик ошибочно направлял их через преобразование BF16; `Q2_0` и `Q8_0` остаются нативными. Не все неизвестные типы объявляются поддержанными.
2. `tools/strata_pack.py`: запрет молчаливой перезаписи готового пакета по признакам `manifest.json`, `index.txt`, `native_experts.txt`; явно заданный `--force` сначала инвалидирует старые маркеры, чтобы прерванная перезапись не оставила старую идентификацию на новых бинарных данных. Существующие частные Q4/Huihui/IQ3_S профили не изменяются.
3. `src/kernels/ngram.cpp`: для Q8_0 PLE и остальных таблиц проверка арифметики `row_count * row_bytes`, границ data section, смещения тензора и точного размера одиночного шарда теперь выполняется **до** получения указателя на данные. Удалено опасное `offset + need` с возможным переполнением. Форматы/вычисления при допустимом GGUF не менялись.
4. `include/strata/kernels/ple_bounds.hpp`, `tests/cpu/ple_bounds_test.cpp`, `CMakeLists.txt`: вынесенный constexpr-предикат и отдельная CPU-проверка без модели/GPU.
5. `tools/model_compat.py`: новый автономный инструмент для **офлайн-аудита заголовков** GGUF. Проверяет комплектность сплитов, повторы, split.no/count, архитектуру, типы квантования, размер и границы тензоров, нативность PLE, наличие экспериментальных Q6_K/Q8_0 веток. Форматы результата: человекочитаемый и JSON. Вывод **не утверждает**, что полная модель запустится.
6. `tools/test_model_compat.py`, `tools/test_native_ple_key_policy.py`, `tools/test_strata_pack_safety.py`: синтетические проверки без реальных весов и API-ключей. Состояние относительно донора подробно в `DONOR_AUDIT.md`.

## Важные ограничения

- Наличие нативных Q8_0/Q6_K веток и PLE-ключей не означает полноту end-to-end загрузки любой модели Unsloth/Huihui.
- Предложенная проверка GGUF читает только локальные заголовки. Больше не использует утверждения донора «known == запускается», которые не обоснованы опытом нашей версии.
- Принудительная перезапись пакета (`--force`) потенциально разрушительна для выбранного каталога; без явного флага защита включена по умолчанию. Публичные абсолютные пути и приватные модели не переносились.
- До завершения полного покрытия кодовой базы остаются задачи в `TASKS.md`. **100% готовности проекта не заявляем.**
