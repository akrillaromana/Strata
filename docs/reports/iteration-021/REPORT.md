# Strata Custom 021 — строгий GGUF-мультишардный нативный dense path

**База:** полный ZIP 020. Пользователь сообщил, что 020 применена; SHA нового Git HEAD он не прислал, поэтому НЕ считать известным.

## Изменения исходников

- `src/core/native_dense.cpp`: `NativeDense::served_names` и `NativeDense::load` теперь открывают `GgufModel` всего семейства шардов, проверяют общую архитектуру. Исчезла ручная частичная проверка первого/дополнительных шардов, которая не сверяла общий итог `split.tensors.count` и могла принять неполный список. Никакой CUDA-буфер не выделяется до завершения этой общей проверки. В discovery теперь требуется корректное расположение байтов каждой выбранной нативной матрицы.
- `include/strata/artifact/gguf_reader.hpp`: не допускаются дублированные метаданные (в частности split и architecture), опасные длины строк/заголовков, огромные фиктивные счётчики, пустое mmap-отображение, некорректный `general.alignment`, неверные типы split-метаданных, отрицательные counts. Обеспечено совместимое чтение GGUF-типов `U16` для `split.no`/`split.count` и `I32` для `split.tensors.count` (формат llama.cpp). Сохранено прежнее сообщение для попытки открыть первый шард как целую модель.
- `tools/gguf_reader.py`: аналогичные меры в Python-header-ридере, который используется `model_compat` и проверкой состава личных GGUF. Строго проверяются длины строк, количество записей, имена и выравнивание.
- `include/strata/artifact/gguf_split.hpp`: увеличен буфер для форматирования номера шарда, устраняющий `-Wformat-truncation` / `-Werror` при сборке C++-тестов GCC.
- CMake + автономные CPU-only C++ и Python тесты. C++ fixture проверяет правильную геометрию блоков Q6_K (256/210), Q8_0 (32/34), отказ при противоречивой архитектуре, неполном split, дублях, обрезанных заголовках и неверном выравнивании.
