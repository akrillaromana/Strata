# Исходный MTP GGUF и runtime — различие

- BF16 (`GGML_TYPE_BF16=30`) и Q8_0 (`GGML_TYPE_Q8_0=8`) Unsloth MTP GGUF — **исходные веса**.
- Старый `tools/mtp_rt.py` принимает только packed GGUF с Q2_0 experts (`GGML_TYPE_Q2_0=42`).
- Новый `tools/mtp_original_rt.py` может **явно, по запросу** преобразовать полный исходный BF16/Q8_0 GGUF в существующий runtime с Q2_0 routed experts; это **потеря качества**, не полное нативное Q8_0/BF16 исполнение.
- Командная строка в справке самого инструмента является описанием его формата, не заданием владельцу запускать модель или устанавливать приложение. Эта итерация не требует исполнения конвертера на его компьютерах.
- Конвертер требует, чтобы `--out` отсутствовал, не меняет исходный GGUF, не смешивает разные MTP-файлы, не записывает результат в действующие E:/R:.
- Для "shared" GGUF, в котором нет обоих routed experts, будет явная ошибка — корректное объединение требует исследования настоящих метаданных, нельзя предполагать совместимость по имени.
- Существующий drafter использует Q2_0, поэтому прямой GPU BF16/Q8_0 ещё предстоит реализовать. Этот обходной инструмент не должен считаться завершением данного требования.
