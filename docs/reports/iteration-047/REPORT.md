# Strata Fork — итерация 047: метка RAM-диска и неизменяемые пользовательские конфигурации

Дата: 13 октября 2026. Основа — полный `Strata-Fork-IQ3S-iteration-046.zip`.

## Новые факты с Windows

- Q8_0 ранее запускалась, комплект шести Q8 GGUF и нативный пакет прошли подготовку, калибровщик выдал 15.100 → 16.900 токена/с (+11.921%, PCIe 0.20, MTP/spec-min-p 0.90). Сохранённая автокалибровка относится к прежней неизменённой сборке `strata.exe`.
- В 046 повторный запуск прервался **до** проверки Q8 PLE и до сервера: существующий R: имеет NTFS, размер 64.00 GiB и метку `RamDisk`, а `Ensure-StrataModelRamDisk` жёстко требовал `STRATA_PLE`. Двигатель/калибровка не были причиной именно этого отказа.
- Пользователь дополнительно сообщил, что изменения JSON в корне и PERSONAL_START пропадают после запуска. Проверкой исходников выявлены атомарные перезаписи конфигураций в четырех запускателях: IQ3_S, Q4_K_XL, Huihui, Q8_0. Сценарии вновь подставляли значения шаблонов (`--pcie-frac`, `--spec-min-p`, `--kv`, `--spec` и т. д.).

## Исправлено

1. `STRATA-MODEL-LAUNCH-COMMON.ps1`: для **существующего R:** допускается устаревшая метка `RamDisk` при NTFS, ёмкости ≥60 GiB и наличии распознаваемого файла кэша Strata (Q8/IQ3/Q4) **или** подтверждённого через Windows Storage устройства Arsenal/ImDisk RAM. Старый том не переименовывается/форматируется. Незнакомый том с той же меткой без этих признаков по-прежнему блокируется. Новый AIM RAM-диск создаётся с меткой `STRATA_PLE`.
2. Q8_0, Q4_K_XL, Huihui теперь полагаются на эту общую проверку и не отвергают `RamDisk` повторно.
3. Новая функция `New-StrataModelRuntimeConfig`: выбирает исходный JSON из корня проекта, а при отсутствии — из `PERSONAL_START_E_ai_Strata-Q4-Fork`. Читает его только для чтения, сохраняет все пользовательские аргументы и настройки (семплинг, контекст, токены, PCIe, MTP, ключ API, параметры моделей и дополнительные поля). Меняет **только в отдельном временном JSON** пути запущенного экземпляра: `--pack`, `--native`, `--expert-profile`, `--mtp`, у IQ3_S `--ple-gguf`, у Q8 обязательный `--ple-require-type Q8_0`; `exe`, `cwd`, `tokenizer`, `log`, `lib_dirs`, идентификатор модели и фактический bind. Исходный JSON при запуске не открывается на запись.
4. Все четыре запуска в корне и соответствующие личные/зеркальные файлы `tools/windows/q4-local-profiles/` используют **runtime JSON в `logs/.../runtime-*.json`** вместо корневого `strata-*.json` на серверной командной строке. Обновлены зеркальные копии и проверка `tools/TEST-MODEL-LAUNCHERS.ps1`.
5. `-IgnoreAutotune` для Q8/IQ3_S отключает применение сохранённого профиля только на текущий запуск и не модифицирует пользовательские JSON. Обычный режим сохраняет пользовательский `autotune=false`, если он задан; иначе Python-сервер применяет проверенный файл из `model-autotune`, не изменяя исходную конфигурацию.
6. Добавлен `tools/TEST-CONFIG-IMMUTABILITY.ps1`: безопасно проверяет с временными тестовыми файлами источник в корне/личном каталоге, приоритет, сохранность аргументов и семплинга, неизменность SHA-256 обоих пользовательских JSON, резервный источник, `-IgnoreAutotune` и отказ от некорректного JSON. Не запускает модель или AIM.

## Ограничения

- **Приоритет конфигурации:** если корневой JSON уже существует, он считается основным. Изменения только личного JSON не применятся к этой модели, пока корневой файл используется. Сообщение о выбранном источнике будет напечатано явно.
- Полный ZIP сохраняет оригинальные персональные JSON из 046 для воспроизводимости. При ручном обновлении **не затирайте свои уже отредактированные пользовательские JSON файлами из ZIP**: запрет перезаписи *во время запуска* не может отменить перезапись при распаковке.
- Если R: полностью очищен после перезагрузки, а Storage не позволяет определить тип устройства, скрипт остановится с диагностикой вместо работы с потенциально чужим диском.
- Корректность Windows PowerShell 7, AIM и готовность Q8 после обновления **не подтверждены на машине пользователя**. Отдельно сохраняется необходимость фактической верификации применения калибровки и генерации после READY. Не выполнять `-PreparePack` для повторного запуска готового Q8.
- Python C++/CUDA и `serve/server.py` не менялись; `strata.exe` не перестраивать. Исходные GGUF, PLE, MTP и модельные калибровочные файлы не включаются и не изменяются.
