# Итерация 042 — запуск Q8_0 и восстановление запуска Q4/Huihui

## Основание

Пользователь сообщил:

1. `TUNE-MODEL.ps1 -Apply` прошёл все измерения IQ3_S: медиана исходного профиля около 33,4 токена/с, выбранного кандидата около 34,4 токена/с, но изменение не сохранилось при минимальном требовании 3%.
2. В комплекте отсутствовал самостоятельный запускатель исходной модели Unsloth Q8_0, хотя существовал `strata-unsloth-q8_0.json`.
3. При запуске Q4_K_XL из `PERSONAL_START_E_ai_Strata-Q4-Fork/START-Q4-RAM.ps1` возникала ошибка «Не найден обязательный путь: ...\.venv\Scripts\python.exe». Такой же устаревший поиск Python существовал у Huihui.

## Изменения по файлам

- `STRATA-MODEL-LAUNCH-COMMON.ps1` — общий поиск Python 3.10+ (сначала `.venv`, затем PATH), инициализация DLL CUDA/MSVC из уже существующего модуля, проверка занятого порта, вычисление размера файлов и атомарное сохранение JSON с `.bak`.
- `PERSONAL_START_E_ai_Strata-Q4-Fork/START-Q4-RAM.ps1` — снята жёсткая зависимость от `.venv`; используется проверка cuBLAS; реальные каталоги DLL передаются серверу; включено безопасное адресное применение автонастройки; живые сообщения о запросах по умолчанию видны в терминале (старый режим через `-Detached`).
- `PERSONAL_START_E_ai_Strata-Q4-Fork/START-HUIHUI-Q4-RAM.ps1` — те же изменения для Huihui, без изменения его SHA-256 проверок и профиля качества.
- `PERSONAL_START_E_ai_Strata-Q4-Fork/run-unsloth-ud-q4_k_xl.bat` — перенаправлен на исправленный Q4-профиль, прямой вызов отсутствующего `.venv` удалён.
- `PERSONAL_START_E_ai_Strata-Q4-Fork/START-Q8-RAM.ps1` — новая самостоятельная подготовка Q8_0: проверка шести оригинальных GGUF, проверка нативной PLE только типа `Q8_0` существующим `tools/q8_ple_preflight.py`, проверка доступности двигателя/зависимостей, создание либо повторное использование RAM-диска с меткой `STRATA_PLE`, побайтовое содержимое копии PLE защищено проверкой SHA-256, пять остальных шардов остаются на E: и отображаются ссылками, собственный пакет Q8/MTP копируется на R:, исходные файлы не изменяются. Сервер работает в терминале. Отдельные журналы на E:; `--ple-require-type Q8_0` строго сохраняется.
- `PERSONAL_START_E_ai_Strata-Q4-Fork/START-HERE Q8_0.bat` — запуск Q8 через PowerShell 7 с повышением прав. Добавлены корневые `START-Q8-RAM.ps1`, `START-Q4-RAM.ps1`, `START-HUIHUI-Q4-RAM.ps1` и `START-HERE Q8_0.bat` для прямого запуска из корня форка.
- `tools/windows/q4-local-profiles/` — личные шаблоны синхронизированы с поставляемой копией.
- `TUNE-MODEL.ps1` — результат показывает три знака после запятой, порог и разницу до порога, сохраняет точное значение процента в JSON; значения и логика применения не ослаблены.
- `tools/TEST-MODEL-LAUNCHERS.ps1` — проверка синтаксиса восьми PowerShell-файлов без запуска модели и работы с RAM-диском; статические проверки профилей расширены.

## Принятые решения по безопасности данных

- До проверки всех шести GGUF и Q8 PLE **ни один** существующий каталог R: не изменяется.
- Перед переключением на Q8 сервер на порту 8080 и любые обнаруженные процессы Strata из этой установки должны быть остановлены пользователем штатно; запускатель не завершает их принудительно.
- Удалять разрешено только известные временные RAM-каталоги предыдущих моделей (`R:\iq3s-model`, `R:\strata-iq3s-runtime`, `R:\q4-model`, `R:\strata-q4-runtime`) после успешных проверок. Неизвестные файлы на R: не удаляются.
- Диск R: обязан быть NTFS объёмом не менее 60 ГиБ, с меткой `STRATA_PLE`; никакой существующий неподходящий том не форматируется.
- Оригинальные GGUF, пакеты на E:, директории моделей, конфигурации IQ3_S и исходный EXE не изменялись.
- При нехватке собственных Q8-исходников/пакета сценарий останавливается с конкретной ошибкой и позволяет указать `-ModelsDirectory` / `-PackSource`. Не подменять оригинальный Q8 пакет чужим.

## Проверки

- `python -m unittest tools.test_q8_ple_preflight tools.test_calibrate tools.windows.q4-local-profiles.test_personal_profiles`: **36/36 успешно**.
- Сверка двух каталогов личных профилей: успешно, включая новые Q8-файлы.
- Синтаксис PowerShell 7 и фактическая загрузка Q4/Q8/Huihui на Windows не проверялись: в среде разработки нет PowerShell 7, NVIDIA GPU и пользовательских 6 GGUF Q8.
- Новые CUDA-исходники не изменялись; пересборка Strata не требуется.

## Калибровка — пояснение значения около 3%

При отображении 33,4 и 34,4 токена/с вычисление `(34.4 / 33.4 - 1) * 100` даёт примерно 2,994%, то есть чуть меньше 3%. Исходный порог срабатывал по точным значениям, а округлённое сообщение `+3,0%` создавало неверное впечатление о достижении порога. Достоверное сравнение на нескольких прогонах всё ещё требует отдельного проверки на Windows. Не заявлять зафиксированный прирост скорости.
