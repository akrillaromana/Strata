# Strata Custom v0.1.39 — отчёт итерации 002

## Основа и границы

- Форк: `https://github.com/akrillaromana/Strata`.
- Ветка: `strata-v0.1.39-custom`.
- Исходный опубликованный коммит пользователя: `ba8b9d2` («Integrate Huihui GGUF fix and Q4 profiles»).
- Эта итерация продолжает доставку 001, не заменяет `main` и не меняет настройки локальной установки `E:\ai\Strata-Q4-Fork`.
- Изменены файлы `serve/server.py`, `serve/web/index.html`, `serve/web/app.js`, `serve/web/components.css`, `serve/test_server.py`; обновлена документация. Исходники C++/CUDA, установщик, профили Q4 и Huihui не изменены.

## Анализ исходного кода

1. Сервер до этой итерации поддерживал параметры `min_p`, `repetition_penalty`, `presence_penalty`, `frequency_penalty` и `penalty_last_n` в блоке `sampling` конфигурации и преобразовывал их для движка в `min_p`, `penalty_repeat`, `penalty_present`, `penalty_freq`, `penalty_last_n`.
2. Веб-интерфейс не предоставлял элементы управления этими пятью параметрами и не передавал их в собственные запросы.
3. Общая настройка `POST /settings` отвергала эти пять имён, хотя конфигурация и движок уже понимали их. Поэтому сценарий «Use for other apps too» не мог сохранять такие настройки.
4. Нативный C++ движок ограничивает историю штрафов `kPenaltyWindowCap = 4096`, а количество кандидатов в выборке — 64.

## Что выполнено

- Добавлены Min-p, штраф повтора, штраф присутствия, штраф частоты, окно истории штрафов (1–4096) в панель генерации.
- Для Temperature, Top-p, Top-k, Min-p и трёх штрафов реализованы синхронизированные ползунки и поля точного числового ввода.
- Значения сохранены в браузере через существующий механизм `strata.sampling` и передаются в `POST /v1/chat/completions` без перезагрузки модели.
- Нейтральные значения не отправляют лишние ключи: Min-p = 0; повтор = 1; присутствие/частота = 0. При температуре 0 фильтры вероятностей отключены, а штрафы могут применяться к жадной выборке.
- История штрафов включается только при ненулевом штрафе и проверяется на диапазон и целочисленность.
- Реализовано сохранение расширенных параметров в `POST /settings`; внешний клиент сохраняет приоритет над общими значениями.
- Сервер проверяет типы, диапазоны и конечность чисел общих значений; неверные запросы возвращают HTTP 400 и не заменяют действующий профиль.
- Добавлены регрессионные проверки, включая передачу параметров к движку, приоритет запроса, нейтральные значения, отклонение некорректных значений и наличие полей в веб-интерфейсе.

## Фактически выполненные проверки

- `python -m py_compile serve/server.py serve/test_server.py` — пройдено.
- `node --check serve/web/app.js` — пройдено.
- `python -m unittest serve.test_server.SharedSettings serve.test_server.SamplingKeys serve.test_server.WebApp serve.test_server.ClientShapes serve.test_server.ThinkingBudget -q` — **40 проверок, успешно**.
- `python -m unittest serve.test_runconfig serve.test_security serve.test_responses -q` — **50 проверок, успешно**.
- Полный `serve.test_server` был запущен, но превысил лимит 120 секунд и прерван; итоговый результат для полной группы не установлен. Его нельзя считать успешным.
- Тесты взаимодействия с настоящим NVIDIA GPU, сборка Windows и визуальная проверка в браузере не выполнялись.

## Что не сделано и почему

- Настройки последовательностей остановки, структурированного JSON, политики переполнения контекста, параметров потоков CPU и профилей импорта/экспорта: требуют отдельной проверки соответствия API/C++, а не добавления фиктивных контролов.
- `top_k = 0` как полностью отключённая фильтрация: текущий движок переводит это значение в 64 кандидата. Для настоящего отсутствия ограничения нужна отдельная правка движка C++ и проверка эффективности/правильности.
- «Внешняя модель-черновик» для спекулятивной выборки: штатный MTP не равен произвольной модели-черновику; не реализовано.
- Унаследованный патч бюджета рассуждений через cookie не реорганизован. Принудительно менять проверенную логику Huihui/Q4 в этой итерации не стали.
- Полная проверка всех сторонних API-клиентов, всех платформ и графического интерфейса — впереди.
