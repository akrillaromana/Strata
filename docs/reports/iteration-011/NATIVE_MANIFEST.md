# Контракт нативного манифеста экспертов (до и после 011)

Файл `native_experts.txt` генерируется `tools/iq_pack.py`; он задаёт один GGML type ID пары gate/up, другой type ID для down, размер каждого native expert blob, оффсеты каждого GGUF-ролевого тензора и имя shard. С версиями v3/v4 совместимость сохранена: v3 описывает один файл на слой, v4 — `gate,up,down` для смешанных шардов (пустое имя в роли означает первичный `--native` GGUF). Данные Q6_K хранятся в собственных квантованных блоках, аналогично Q8_0 и Q4_K.

Прежде C++ loader использовал `at += blob * n_expert` без проверки переполнения и допускал некорректные дубли/имена шардов. Итерация 011 проверяет:

- `0 < layer_count`, `0 < expert_count`, ограничения размера таблицы и целые type IDs до обращения к ggml CPU traits;
- одну запись на слой, отсутствие пробелов или мусора после каждой корректной строки;
- тип, длину blob, суммы по экспертам и диапазоны всех ролей не дальше физического файла;
- отсутствие `..`, абсолютных и UNC путей, дисковых префиксов и разделителей пути в именах GGUF-шардов;
- точные сегменты 3-ролевой раскладки и несовместимых версий, без превращения Q6_K в BF16.

Ограничение: это **защита и улучшение фактического C++ пути чтения весов**, но не доказательство численной корректности CUDA Q6_K, не подключение отсутствующих WMMA-ядер 0.1.41 и не поддержка произвольной мультимодальной Huihui Q8_0 архитектуры. Проверки на GPU остаются отдельной будущей фазой после завершения кода.
