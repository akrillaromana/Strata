# Итерация 011 — нативная безопасность Q6_K/Q8_0/Huihui + исправления публикации

**Исходный код:** полный ZIP 010 поверх неизменяемой основы upstream 0.1.39. Последний подтверждённый пользователем `git push`: `67290b9` (010); **011 ещё не опубликована**. Применять к ветке `strata-v0.1.39-custom` только выбранные исходники. Внешнюю установку, CUDA-сборку и запуск GGUF пользователь пока запретил.

## Выполнено в коде

1. `src/kernels/cpu/expert_layout.cpp`: C++ parser `native_experts.txt` с проверками целых размеров, версий, счётчика экспертов, отсутствия дублей слоёв, полноты triplet GGUF offsets, остаточных полей, безопасных локальных имён шардов и арифметики общего объёма экспертов. Исключены отрицательные/нулевые значения, повторные строки и переполнения. Сохранена возможность v3/v4 многосегментного разбиения `gate,up,down`.
2. `src/kernels/cpu/native_expert.cpp`: проверка допустимости GGML type ID **до** доступа к таблице traits, числовые проверки размеров `n_embd`, `n_ff`, буферных смещений, суммарного размера native expert blob. Изменения затрагивают общий путь Q6_K (14), Q8_0 (8) и IQ, а не переименовывают модельные профили.
3. `src/core/expert_source.cpp`: обе реальные ветви нативного чтения (`FileExpertSource::open_gguf` и `check_experts_gguf`) используют проверяемое умножение `role_bytes * n_expert` и диапазон `offset .. end`; для повреждённого GGUF `data_start > file_size` нет арифметического переполнения. Сопоставление offsets выполняется только после установления, что диапазон лежит в файле.
4. `include/strata/kernels/cpu/native_layout_safety.hpp` + `tests/cpu/native_layout_safety_test.cpp`: отдельная проверяемая реализация checked arithmetic и отказа на опасные имена файлов; CMake-цель регрессионного C++ теста без CUDA/ggml.
5. `tools/donor_audit.py`: генерация пятиколоночной TSV матрицы с явным `-` для отсутствующего SHA; `tools/test_donor_audit.py` проверяет отсутствие завершающих табуляций; существующая `docs/reports/iteration-010/DONOR_FILE_MATRIX.tsv` исправлена без изменения количества записей/статусов/известных SHA. Это устраняет коренную причину ошибки публикации 010.
6. `serve/telemetry.py`: контекстные менеджеры для чтения `/proc/{cpuinfo,stat,meminfo}` во всех успешных и исключительных ветвях; `serve/test_telemetry_files.py` содержит синтетические проверки закрытия файлов.

## Реальные локальные проверки

- C++ header-only native layout test: `native_layout_safety OK` (`g++ -std=c++20 -Wall -Wextra -Werror`); синтаксис `expert_layout.cpp` проверен также с `-DSTRATA_NATIVE_EXPERTS`.
- Python: **76/76** проверок выбранного набора, включая новые telemetry и TSV; `docs/reports/iteration-011/CHECKS.txt` содержит состав групп.
- Node: **55/55** проверок client-side chat, presets и JSON-formats.
- Дополнительный изолированный C++ parser harness: **10/10** синтетических сценариев ожидаемого принятия/отказа.
- TSV: **2506 строк** с заголовком, ровно пять полей в каждой строке, без завершающих пробелов или табуляций.

**НЕ выполнено:** компиляция полного C++/CUDA движка, запуск GGUF или пользовательские внешние тесты — по указанию пользователя. Отдельный `.cpp` синтаксически проверен, но `native_expert.cpp` зависит от внешнего ggml, а `expert_source.cpp` от CUDA SDK, отсутствующих в этой среде. Это не подтверждает end-to-end моделей. Итерация улучшает путь native expert load, но **не закрывает** native Q6_K/Huihui Q8_0 до полной кодовой готовности.

## Предупреждения

- `tools/donor_audit.py` остаётся инструментом сравнения по содержимому, а не автоматическим интегратором всего донора 0.1.41.
- Сохраняются собственные Q4_K_XL/IQ3_S/Huihui Q4_K_XL, настройки sampling/API, история нескольких чатов и генерация JSON Schema.
- Браузер/сервер на машине пользователя не тестируются. Не приписывать локальные синтетические проверки к CUDA-прогонам.
