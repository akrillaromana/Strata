# Итерация 022 — полная GGUF payload preflight для Q6_K/Q8_0

**База:** Strata-custom-v0.1.39-iteration021-FULL.zip; опубликованный коммит 021 `b67bf1e` (подтверждён логом пользователя). Публикация 020 — `2ffd418`. Архив 022 включает полное дерево исходников, ничего из 001–021 не удалено.

## Проблемы

1. Python `TensorInfo.expected_bytes()` разрешал квантованный тензор со строкой в 128 элементов Q6_K и двумя строками (`[128, 2]`): глобальные 256 элементов кратны 256, но каждый GGUF-квантовый блок не может пересекать границу строки. C++ `tensor_payload_bytes()` уже отклонял такое. Значит, `model_compat`/`personal_models --check` мог объявить невалидные Q6_K данные структурно подходящими.
2. `NativeDense::served_names()` в 021 проверял лишь границы отдельных выбранных матриц и мог пропустить повреждение/пересечение соседнего тензора. `NativeDense::load()` имел собственный независимый цикл диапазонов, так что предварительное обнаружение и фактическая загрузка отличались.
3. `NativeDense::load()` проверял payload каждого шарда непосредственно перед его загрузкой, а не всех шардов **до первого** `cudaMalloc`. Повреждение позднего шарда приводило к лишней загрузке ранних шардов до отказа.

## Реализовано

- `include/strata/artifact/gguf_reader.hpp`: `validate_native_tensor_layout(const GgufFile&)` отдельно от мягкого header-only просмотра обычных GGUF. Проверяет типовую блочную геометрию **строки**, не-нулевые размеры, переполнения, кратность каждого tensor offset `general.alignment`, байты в границах файла, корректность и непересечение диапазонов в пределах шарда (с проверкой тензоров, которые не будут нативно загружены).
- `src/core/native_dense.cpp`: оба пути `served_names`/`load` вызывают одинаковую функцию на **каждом** шарде целиком; `load` заканчивает весь preflight до любой GPU-аллокации. Удалён дублировавший эту проверку локальный код. Q4/IQ3 пользовательские профили не изменялись.
- `tools/gguf_reader.py`: исправлена `expected_bytes` с `elements % block` на `shape[0] % block`, исключены пустые размеры, добавлена `validate_native_payload_layout()` с теми же правилами, что в C++.
- `tools/model_compat.py`: строгий офлайн-аудит перед подсчётом квантований; недопустимый tensor в невыбранной роли тоже блокирует положительный результат. Ранее существовавшие тестовые GGUF-файлы подправлены для настоящего 32-байтового выравнивания.
- Автономные `tests/cpu/native_tensor_payload_test.cpp`, `tools/test_native_payload_layout.py`: корректная пара Q6_K/Q8_0, некратная строка Q6_K, пересечения, дубликат offset, некратный offset, укороченный payload, нулевая строка, чрезмерные размеры, чужой формат. Добавлено CTest-правило. Контрактные тесты 021 обновлены под единую функцию проверки.

## Ограничения и реальная готовность

Это настоящие изменения C++ загрузочной цепочки и Python-проверки. CUDA ядра не компилировались/не запускались, вычислительная точность всех 8 персональных моделей не установлена. Нет реальных файлов GGUF для проверки содержимого; ни один запуск не делался на ПК пользователя. Всё ещё открыты полный end-to-end Q6_K и Huihui/Unsloth Q8_0, 4 MTP и 2 shared GGUF по фактическим заголовкам, Vision/mmproj, token-level JSON Schema, задачи донора 0.1.41. Проект не 100%.
