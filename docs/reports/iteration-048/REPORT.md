## Перенос решений из 0.1.43.1 (выборочный, не 1:1)

1. **Ожидание FIFO:** `serve/server.py::Service.run` теперь отправляет событие `ping` каждые 10 секунд (в тестах частота снижена до 20 мс). Отмена клиентом запроса во время ожидания снимает его с очереди до захвата блокировки; `generator.close()` тоже уменьшает счётчик queued. Логика разработана по upstream #1619 с сохранением нашего парсера, формата API, MTP и политики сериализации ядра.
2. **Очередь TCP:** `Server.request_queue_size` увеличена со стандартных 5 до 256 с конфигурированием `STRATA_HTTP_BACKLOG`, по upstream 0.1.43.1. Windows-защита от двойного bind без SO_REUSEADDR оставлена без изменения.
3. **RAM-диск:** `Ensure-StrataModelRamDisk` принимает отсутствие метки существующего NTFS R: не автоматически, а только при наличии достоверных файлов Q8/IQ3/Q4 либо распознанного виртуального устройства. Чужой том не форматируется, метка не меняется, не происходит стирания.
4. **Приоритет JSON:** сохранили принцип 047 — исходные конфиги root/PERSONAL_START read-only, отдельный runtime JSON в logs. Дополнительно `host`/`port`, если заданы пользователем, не заменяются шаблонными значениями.
5. **Команды Windows:** семь новых BAT в корне: запуск четырёх профилей, общий бенчмарк, универсальный калибровщик и последовательный тест API. Используется PowerShell 7 без `.venv`, нет скрытой перезаписи JSON.
6. **Новые инструменты:** `BENCHMARK-MODEL.ps1` подхватывает реально загруженную модель через API и фиксирует реальные `timings`; `TEST-REQUESTS.ps1` шлёт 6 последовательных запросов в одном растущем диалоге, проверяет ответы, пишет JSON с измерениями и при ошибке захватывает `/health`, `/status`, `/v1/status`.

## Что НЕ переносили

Из 0.1.43.1 не заменяли массово сервер, C++/CUDA, размещение экспертов, форматы моделей, многочастные GGUF, PLE, KV, MTP, алгоритмы семплинга. Сильно изменившиеся в 0.1.43.1 компоненты управления сессиями, reasoning-loop recovery и другие функции требуют отдельных регрессионных проверок с текущим форком, поэтому здесь они не объявляются реализованными. Это важно для сохранения качества/производительности IQ3_S, Q4_K_XL и Q8_0.

## Результаты для пользователя

Сначала остановить предыдущий сервер, обновить файлы, запустить нужную модель соответствующим BAT/PS1. Вторым окном выполнить `tools/TEST-MODEL-LAUNCHERS.ps1`, `tools/TEST-CONFIG-IMMUTABILITY.ps1`, затем `TEST-REQUESTS.ps1`, `BENCHMARK-MODEL.ps1`. Для подбора — `TUNE-MODEL.ps1 -Apply` или `TUNE-MODEL.bat`. Приложить файл `logs/request-tests/REQUEST_TEST_LAST.json` и server/engine логи при повторном зависании. Результаты autotune Q8 `pcie_frac=0.2`, `spec_min_p=0.9` не удаляются.

**Известное ограничение:** если движок реально не отвечает и его процесс остаётся занят, FIFO keep-alive не устраняет первопричину. Существующая защита `engine_silence_s` по умолчанию 300 секунд сохранена; нужно получить журнал остановившейся сессии Windows до решения о перезапуске/изменении CUDA.
