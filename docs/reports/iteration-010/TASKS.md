# Открытые задачи после итерации 010 (исходный код, без пользовательских испытаний)

## P0 — основные требования

- [ ] Полноценный нативный Q6_K: GGUF, pack, expert, prefill, grouped, CPU/CUDA MMVQ и память, без обязательного BF16-конвертирования; экспериментальные CUDA-ветви 006 пока не считаются end-to-end.
- [ ] Нативный Q8_0 n-gram **и полная Q8_0-модель**: PLE строка сама по себе недостаточна для полного GGUF/Huihui.
- [ ] Полная кодовая поддержка Huihui Q8_0 multishard с собственными пакетами и допустимыми комбинациями тензоров; сохраняя фикс Huihui Q4_K_XL.
- [ ] Ревизия всех типов квантования и модельных семейств донора 0.1.41, включая Swift/Coder, дополнительные IQ, нестандартные low/high-bit experts; различать признанный формат и работающий backend.
- [ ] Завершить все отсутствующие функциональные модули донора 0.1.41 по `DONOR_AUDIT.md` и `DONOR_FILE_MATRIX.tsv`, без перезаписи собственных исправлений.
- [ ] Внедрить нативный token-level constrained JSON/JSON Schema, включая streaming и Anthropic, с чётким отказом на неподдерживаемые схемы.
- [ ] Полноценная панель generation/runtime: seed, cpu threads, repetition bounds, context overflow, KV dtype/resident, MTP/depth/порог, reasoning budget, динамические безопасные изменения, профили всех наших моделей Q4_K_XL/IQ3_S/Huihui.

## P1 — перенос зрелых возможностей донора

- [ ] Session-file/snapshot persistence для движка (отдельно от браузерного экспорта чатов), безопасность и модельная привязка состояния.
- [ ] VMM/DMA/exchange memory and adaptive expert scheduling, исключение нарушения резидентной памяти и многокарточного маршрута.
- [ ] Новый speculative acceptance (probabilistic) с correct top-k/top-p/min-p/repetition и детерминированными seed.
- [ ] Архитектурные CPU AVX2, CUDA WMMA/PDL, HIP/AMD и SYCL/Intel функции с контролем платформенных ветвей.
- [ ] Оставшиеся улучшения стабильности API, очереди, cancel/abort, batch slots, request hardening, concurrency.
- [ ] Проверить что `serve/prometheus.py` не нарушает JSON/metrics и авторизацию при необычном Accept/URL (часть тестов уже написана).

## P1 — устойчивость, безопасность, целостность

- [ ] Модельная диагностика отсутствующих shard, повторов split, fake offset, tensor size, ngram metadata и конфигурация маршрутов загрузки — не смешивать кодовую и фактическую аппаратную поддержку.

- [ ] Безопасное переключение моделей и профилей без жёстких E:/R: путей при сохранении исходных частных настроек.
- [ ] Ревизия безопасности исходных URL/заголовков в новых инспекторах; не допускать загрузки весов вместо чтения заголовка.
- [ ] Устранить обнаруженные `ResourceWarning` из `serve/telemetry.py` (чтение /proc без закрытия файлов).
- [ ] Создать проверяемую матрицу реального покрытия всех донора `Strata-main(2).zip` и зафиксированных user requirements, переоценивая её после каждой итерации.
