# Vision-энкодер: RAM по умолчанию, VRAM по востребованию

`strata-vision` больше не занимает видеопамять при старте сервера.

## Поведение

- При старте сервера энкодер (`strata-vision.exe`, llama.cpp mtmd + mmproj) запускается
  с флагом `--gpu-on-demand`: веса mmproj загружаются в оперативную память, CUDA-контекст
  не создаётся, VRAM не тратится.
- Когда приходит первый запрос с картинкой, сервер:
  1. просит expert cache движка освободить `elastic_mib` (по умолчанию 2048 MiB)
     через `POST /v1/vram` (движок работает с `--vram-elastic`, сервер добавляет его сам);
  2. отправляет энкодеру команду `GPU` — тот освобождает CPU-контекст и загружает
     mmproj на GPU с прогревом;
  3. кодирует картинку на GPU.
- После простоя `elastic_idle_s` (по умолчанию 120 с) без картинок сервер отправляет
  команду `RAM`: веса возвращаются в оперативную память, VRAM отдаётся expert cache.
  Процесс энкодера остаётся живым, поэтому следующий переход в GPU быстрый.
- Если GPU отказал — энкодер продолжает кодировать на CPU, картинки не теряются.

## Управление

- Ключ секции `vision`: `"gpu_on_demand": true|false`. По умолчанию включён, когда в
  секции есть `"gpu": true`; `"gpu_on_demand": false` возвращает старое eager-поведение
  (`--gpu`, VRAM с самого старта).
- `elastic_mib`, `elastic_idle_s` настраивают долю VRAM и простой.

## Протокол strata-vision

stdin-команды: `ENC <img> <out>`, `GPU`, `RAM`, `QUIT`.
Ответы: `OK ...`, `GPU OK <ms>`, `RAM OK`, `ERR <msg>`.
