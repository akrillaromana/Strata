# Нативные высокоточные варианты: Q6_K, Q8_0, Huihui Q8_0

**Статус:** экспериментальные конфигурации. Файлы `*.example.json` — **образцы с несуществующими путями**, а не готовые к запуску профили. Не переносить автоматически в рабочую `E:\ai\Strata-Q4-Fork`.

## Что означает «нативный»

- Для таблицы n-gram `per_layer_token_embd.weight` типа **Q8_0** движок теперь читает настоящие строки 170 байт (пять блоков по 34 байта), не требует предварительной замены таблицы на FP8/IQ4_NL и не меняет веса на диске.
- Для экспертов **Q6_K** ядра обработки токенов, окна групповых экспертов и предзаполнение используют исходные Q6_K-блоки. Эти ядра включаются при сборке (`-DSTRATA_Q6K_EXPERTS=ON -DSTRATA_MMQ_KQUANTS=ON`), но их реальная совместимость с моделью должна быть проверена на NVIDIA GPU.
- У Q8_0 в Strata уже существовала часть нативных путей экспертов, но это **не гарантия**, что произвольный Q8_0 GGUF загрузится. Формат PLE, геометрия, разбиение, индексы, плотные тензоры и структура пакета должны совпасть с ожиданиями `0.1.39`.
- Команда `tools/iq_pack.py --compat-bf16` может преобразовывать некоторые небольшие плотные тензоры в BF16 для работы текущего движка. **Нативными остаются эксперты и PLE**, а не обязательно абсолютно все тензоры. Без такого разделения утверждение о стопроцентной нативности было бы ложным.

## Проверка модели и подготовка пакета

Для каждого нового GGUF отдельно проверяй точное имя и точный размер в байтах; SHA не вычисляется. Затем в корне репозитория, используй Python с доступными зависимостями:

```powershell
python tools/iq_pack.py --gguf "C:\ПУТЬ\К\МОДЕЛИ\ПЕРВЫЙ_СЕГМЕНТ.gguf" --out "C:\ПУТЬ\К\ОТДЕЛЬНОМУ_ПАКЕТУ" --compat-bf16
if ($LASTEXITCODE -ne 0) { throw "Пакет не создан" }
```

Не использовать pack оригинального Unsloth для Huihui: её веса могут отличаться. Не копировать 54 ГиБ Q8 PLE в RAM-диск с недостаточным объёмом, особенно если там уже размещена Q4 PLE. По умолчанию PLE может считываться через отображение файлов с исходного диска.

## Экспериментальная сборка Q6_K на отдельном Windows-компьютере

Запускать из Developer PowerShell Visual Studio; все инструменты (`cmake`, `ninja`, `cl`, `nvcc`) должны работать. Конкретный путь к исходникам заменить:

```powershell
$CMake = "C:\Program Files\CMake\bin\cmake.exe"
$Src = "A:\worklab\project\App\Strata\Strata"
$Build = "A:\worklab\project\App\Strata\_build-q6k-sm86"
& $CMake -S $Src -B $Build -G Ninja -DCMAKE_BUILD_TYPE=Release -DSTRATA_ENABLE_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=86 -DSTRATA_MMQ_KQUANTS=ON -DSTRATA_Q6K_EXPERTS=ON -DSTRATA_BUILD_TESTS=ON
if ($LASTEXITCODE -ne 0) { throw "Ошибка настройки CUDA" }
& $CMake --build $Build --target strata native_expert_parity native_grouped_parity ple_reader_test ple_q8_row_test --parallel 4
if ($LASTEXITCODE -ne 0) { throw "Ошибка сборки" }
& "C:\Program Files\CMake\bin\ctest.exe" --test-dir $Build -R "^(ple_q8_row_test|ple_reader_selftest|native_grouped_parity|native_expert_parity_q6_K_q8_0)$" --output-on-failure
if ($LASTEXITCODE -ne 0) { throw "Одна из проверок не прошла" }
```

Участок `STRATA_Q6K_EXPERTS` **не входит в сборку Q4 по умолчанию**. При нехватке зависимостей установку прекратить и прислать полный журнал; никакой подмены готового рабочего `strata.exe`.

## Пробная загрузка

Скопируй подходящий `*.example.json` в **отдельное** имя, замени все `C:/ABSOLUTE/PATH/TO/...` реальными путями своей машины и проверь имена и точные размеры GGUF. Используй отдельный `strata.exe` и локальный порт `8081`, пока не прошли проверки загрузки и генерации. Пользовательский Q6_K состоит из пяти GGUF. PLE и остальные шарды не нужно полностью дублировать в 64-ГиБ RAM-диске; по умолчанию используются ссылки на исходные файлы.

Huihui Q8_0 отдельно пока не проверена на настоящих GGUF: нужны точный набор шардов, инвентаризация типов тензоров и тест качества ответа, а не только успешный `READY`.


## Готовый Windows-путь Q6_K в форке, итерация 050

Ручной пример выше оставлен как справка. В корне форка теперь есть `BUILD-Q6-ENGINE.bat`, `PREPARE-Q6.bat`, `START-Q6-K.bat`, `START-HERE Q6_K.bat`, `BENCHMARK-Q6.bat`, `TUNE-Q6.bat`, `TEST-Q6.bat` и `GET-Q6-DIAGNOSTICS.bat`. Q6 использует отдельный `engine-q6\strata.exe`; рабочий `engine\strata.exe` других квантов не заменяется. Пользовательский Q6_K состоит ровно из пяти шардов `Qwen3.8-Flash-Next-Q6_K-00001-of-00005.gguf` ... `00005-of-00005.gguf`. PLE по умолчанию остаётся на исходном SSD; `-PleToRam` — явная опция. Пользовательский JSON запуска не перезаписывается.
